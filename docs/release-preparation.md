## Registry-graph performance

The existing equivalent-workload release benchmark was rerun three times against
upstream, with the same io::sink, timestamp/target settings and independent filter,
1,000 warm-up iterations, 20,000 measured iterations and seven alternating-order
samples. Below are medians of three per-run medians in ns/iteration.

| Workload | Owned registry | Upstream JSON | Owned / upstream |
| --- | ---: | ---: | ---: |
| Events | 477.55 | 557.11 | 0.86 |
| Three reused spans | 676.83 | 1851.01 | 0.37 |
| Update plus event | 4457.55 | 2122.80 | 2.10 |
| Updates only | 1945.11 | 455.55 | 4.27 |
| Create span, emit once, close | 2355.19 | 1614.55 | 1.46 |

[Raw summaries](measurements/registry-2026-10-23/) retain all runs, including noisy
samples. These are microbenchmarks, not real sink/application measurements, and no
causal speedup over the old Git graph is claimed. Updates and short-lived spans
remain slower than upstream. Earlier receipts describe their earlier dependency
graphs and remain historical evidence.
